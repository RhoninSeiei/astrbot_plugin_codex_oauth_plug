# Codex WebSocket 请求总量与未知结果提示修复

两次失败发生在压缩完成后，工具返回 `outcome_unknown`，聊天模型却转述为图片太大或建议重发。单图 25 MiB 校验不足以保证 Base64 后的 WebSocket 整体消息可传输。

使用实际 openai_oauth Source 的无效事件探测，不包含图片、提示词、生成工具或 response.create：1 KiB 与 8 MiB 消息收到协议错误响应；18 MiB 以及 17,551,748 字节消息均收到关闭码 1009，约 1.6 秒。温蒂莉亚组合的 Base64 图片数据下限为 17,551,748 字节，杂音组合为 18,912,792 字节。原请求没有记录关闭码，因此历史请求的具体关闭码无法追溯；同路径同大小探测证明消息大小限制能够复现其表现。

Matoi 将 Codex 输入图总原始字节控制在 5 MiB 内，为 Base64、JSON 和文本留出空间。两组实际图片离线重新准备后的模拟请求分别为 6,276,842 和 6,709,266 字节。原图未修改。正常 Grok 输入策略保持不变。

Codex OAuth 独立插件修复分支增加 8 MiB 完整 WebSocket 请求预检，超过时在发送前返回 413 且不重试；增加关闭码、请求与接收字节数、协议事件数量、阶段、异常类型和安全错误分类日志，不记录凭据、提示词或图片。Matoi 对 413 明确提示未提交，对已提交但结果未知使用固定准确提示，避免模型推断图片太大、声称成功或建议立即重发。

线上 Codex OAuth 版本落后于仓库最新版，因此仅移植本次 WebSocket 方法补丁和请求大小常量，不携带无关功能变更。仓库版本的 13 项传输测试通过；线上最小补丁版本的 12 项相关测试通过。远端新增的 HTTP 总超时测试不适用于旧线上 HTTP 路径，本次保持该路径不变。

## 实际加载路径与上线范围

后续核对核心 `ProviderManager.dynamic_import_provider`，确认当前 openai_oauth Source 使用 `astrbot.core.provider.sources.openai_oauth_source.ProviderOpenAIOAuth`。独立 Codex OAuth 插件处于禁用状态。因发布前唯一激活检查未通过，没有替换独立插件，也没有重载或启用它；之前准备的候选目录不属于在线插件目录。

Matoi 的三文件修复已完成单次重载、配置不变和文件哈希核验。2026-11-01 按要求撤回未部署的核心补丁；不修改 AstrBot 核心、不重启服务，也不通过运行时替换核心方法绕过此限制。现有总输入预算、压缩和准确错误提示均在 Matoi 插件内生效。

Codex OAuth 独立插件分支保留传输大小预检与关闭码诊断实现，但线上独立插件处于禁用状态，不能将该分支的诊断能力视为当前核心 Provider 的运行能力。当前 Matoi 只能记录公开接口返回的错误类型、状态分类及本地输入大小；如果核心没有提供底层关闭码，插件如实标记为不可用，不推测具体关闭原因。
